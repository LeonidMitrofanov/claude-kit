# SETUP — как развернуть кит на новом проекте

Что владелец делает руками и что после этого делает оркестратор.
Всё, кроме шагов 1–5, автоматизировано.

Шаги 1–5 делаются один раз на проект. Шаг 0 — подключение самого кита.

---

## Шаг 0. Подключить кит подмодулем

```bash
cd <корень проекта>
git submodule add <URL или локальный путь к репозиторию кита> claude-kit
mkdir -p tasks dialog docs
```

Кит лежит в `claude-kit/` и правится только в своём репозитории. Всё проектное —
`project.conf` в корне, шаг 6.

---

## Шаги владельца

### 1. Завести бота у BotFather

В Telegram написать [@BotFather](https://t.me/BotFather):

```
/newbot
<имя бота, как его увидят люди>
<username, обязан заканчиваться на bot>
```

В ответ придёт **токен** вида `1234567890:AAH…`. Он даёт полный доступ к боту —
не пересылать, не вставлять в файлы, никуда не копировать кроме шага 5.

Один бот на проект. Общий бот на два проекта не годится: `getUpdates` отдаёт каждое
обновление ровно один раз, и два приёмника начнут отбирать сообщения друг у друга.

### 2. Приватность — можно не трогать

Классический совет «отключить приватность» здесь **не обязателен**: бот-администратор
получает все сообщения группы независимо от этой настройки. Проверено на двух ботах
этой машины — у работающего `can_read_all_group_messages: false`, и он исправно видит
всё, что пишет владелец.

Отключить всё равно, для страховки:

```
/setprivacy → выбрать бота → Disable
```

Если отключаете — делайте это **до** добавления в группу. Уже добавленного бота
придётся удалить из группы и добавить заново, иначе настройка не подействует.

### 3. Создать супергруппу и включить темы

1. Создать группу, добавить в неё кого угодно вторым участником (Telegram
   не делает супергруппу из группы на одного).
2. Настройки группы → **Темы** (Topics) → включить.
   Группа автоматически станет супергруппой.
3. Создать пять тем:

| Тема | Для чего |
| --- | --- |
| Постановка задач | Задачи от владельца. Здесь живут реакции-статусы |
| Отчёты | Итоги закрытых задач |
| Вопросы | Только то, на что может ответить лишь владелец |
| Важное | Ссылки и постоянные сведения |
| Оркестратор | Разговор вне задач |

Разделение не косметическое: на него опирается `claude-kit/ORCHESTRATOR.md`.
В «Постановке» видно, что происходит сейчас, в «Отчётах» — что сделано;
смешаешь — лента текущих задач утонет в результатах.

### 4. Добавить бота администратором

Настройки группы → Администраторы → Добавить → найти бота по username.

Права, которые нужны:

- ✅ **Управление темами** (`can_manage_topics`) — без него бот не сможет
  ни создать тему, ни писать в закрытую;
- ✅ **Закрепление сообщений** — правила тем и ссылки в «Важном»;
- ✅ **Удаление сообщений**.

**Администратором — обязательно.** Это не про удобство: именно admin-статус даёт
боту видеть все сообщения группы. Обычный участник с включённой приватностью
получит только команды на `/` и ответы на свои же сообщения, и канал будет молчать.

### 5. Положить токен в Keychain

В терминале, подставив своё имя и токен:

```bash
security add-generic-password -a "$USER" -s telegram-bot-token-<проект> -w '<ТОКЕН>' -U
```

Имя ключа **уникальное на машину**: у каждого проекта свой бот и свой токен, общее
имя вроде `telegram-bot-token` приведёт к тому, что второй проект перезапишет ключ
первого и сломает первый.

В репозиторий токен не попадает никогда — скрипты берут его из Keychain по имени.

### 6. Заполнить настройки

```bash
cp claude-kit/project.conf.example project.conf
```

**В корень проекта, а не внутрь кита.** Кит — общий подмодуль; файл, оставленный
внутри него, затрётся при обновлении или уедет в чужой проект. Скрипты ищут
`project.conf` вверх от каталога кита и внутрь него не заглядывают.

Заполнить все `<плейсхолдеры>`. Это **единственный** файл, который нужно править
ради нового проекта. Пояснение к каждому ключу — прямо в нём.

Номер чата: написать что-нибудь в группу и выполнить

```bash
curl -s "https://api.telegram.org/bot<ТОКЕН>/getUpdates" | python3 -m json.tool
```

взять `message.chat.id` — он со знаком минус и префиксом `-100`, так и записывать.

Номера тем узнаются сами: после запуска приёмника они появятся в `dialog/TOPICS.md`.
Тема, где ещё никто не писал, боту не видна — напишите в каждую по сообщению.

Проверить, что всё читается, и заодно убедиться, что корень проекта найден верно:

```bash
claude-kit/tg/kitconf.py
```

Первые строки вывода — найденный корень, путь к настройкам и каталог состояния.
Корень не тот — дальше идти нельзя: скрипты будут писать `dialog/` и `.kit-state/`
не туда.

## Что делает оркестратор

Запустить главную сессию под именем из настроек:

```bash
claude --name "$(claude-kit/tg/kitconf.py ORCHESTRATOR_NAME | cut -d= -f2)"
```

и дать ей прочитать `claude-kit/ORCHESTRATOR.md`. Дальше она сама:

1. Записывает в `.kit-state/` своё имя (`orchestrator.name`, из `ListAgents`)
   и указатель на свой сокет (`orchestrator.sock`, из `$CLAUDE_CODE_MESSAGING_SOCKET`).
   Без первого делегированные сессии получат мёртвый адрес, без второго сообщения
   владельца будут ждать обхода вместо мгновенной доставки.
2. Поднимает приёмник:
   `tmux new-session -d -s tg-poll -c "$PWD" 'claude-kit/tg/tg-poll.py'`.
3. Пишет в каждую тему первым сообщением её правила и записывает их номера
   в `project.conf` (`TG_RULES_*`) — правила потом правятся на месте через
   `tg-edit.sh`, а не заводятся заново.
4. Заводит задачи по `claude-kit/SESSION-REQUEST.md`, запускает их
   `claude-kit/launch-session.sh <slug>` и обходит `claude-kit/sweep.sh`.

Приёмник должен жить постоянно: `getUpdates` отдаёт каждое обновление ровно один раз,
поэтому сообщения складываются в файлы `dialog/`, а не читаются из API на лету.
Пока он не запущен, сообщения копятся на стороне Telegram и придут после старта.

## Грабли, проверенные на прошлых проектах

| Что | Чем оборачивается |
| --- | --- |
| `project.conf` положили внутрь `claude-kit/` | Скрипты его не видят и ругаются на отсутствие настроек. При обновлении подмодуля файл затрётся |
| Правку кита сделали прямо в `claude-kit/` проекта | Уедет к соседям при первом же `push` или потеряется при `submodule update` |
| `.kit-state/` попал в git проекта | Указатель на сокет содержит PID чужой машины, `offset` — чужую позицию в чужом чате |
| Бот — обычный участник, а не админ | Канал молчит: бот не видит обычных сообщений |
| Приватность отключили после добавления в группу | Не действует. Удалить бота из группы и добавить заново |
| Общее имя ключа в Keychain на два проекта | Второй проект перезапишет токен первого |
| `chat_id` записали без префикса `-100` | `Bad Request: chat not found` |
| Два приёмника на одного бота | Сообщения делятся между ними случайным образом |
| `claude` из `PATH` версии ниже 2.1.261 | Сокет обмена не создаётся, `SendMessage` не находит адресатов, и это никак не проявляется, кроме тишины |
| Нет разрешения `Bash(tmux:*)` у оркестратора | Не сможет ни запускать сессии, ни смотреть в них |
| `tmux capture-pane -t <имя сессии>` | «can't find pane». Нужен `pane_id` из `list-panes` — по имени не работает даже с точным `=<имя>` |
| Эмодзи `❓` или `🏁` в реакции | `REACTION_INVALID`. Telegram принимает не любые; проверенные — `👀 👨‍💻 🤔 🏆 😴`. Для значков тем набор ДРУГОЙ: `❓` там принимается |
| Поиск метода «закрепить тему» в Bot API | Его нет. `pinForumTopic` отвечает `Not Found` — закрепляет человек в клиенте |
| Значок темы поставили эмодзи в названии | Значок — отдельное поле `icon_custom_emoji_id`; ставится `tg-topic-icon.sh` |
| При смене значка передали `name` «как было» | Опечатка в названии молча переименует тему. Поле необязательное — не передавать |
